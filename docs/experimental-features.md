## unauthorized：请求重启框架

参考 [Lpaipai/xgimi-adb-guide](https://github.com/Lpaipai/xgimi-adb-guide) 的 [机制分析](https://github.com/Lpaipai/xgimi-adb-guide/blob/main/docs/how-it-works.md)。作者在 NEW Z6X / Android 8 / v12.15.214 中分析到：持久 USB 配置用于初始化框架 ADB 状态，启用授权监听后，厂商代码会自动批准有效电脑公钥。重启只是使配置重新加载，不是重启操作本身批准授权。

本项目按钮流程：用户确认 → 检查持久／运行时 USB 配置为 adb、端口为 5555、adbd 与 zygote 正在运行 → 同步保存一次性尝试标记 → 请求 `setprop ctl.restart zygote`。不修改 ro.adb.secure，不写入 adb_keys，不修改 SELinux。打开应用或开机恢复不会自动触发此操作。

该操作会退出当前应用、暂时断开画面或连接。尝试标记在请求之前保存，即使请求失败也不会自动反复重试。返回桌面后，应在电脑重新连接并执行 shell 验证，提交请求成功不等于授权成功。

本项目尚未在对应 NEW Z6X 上测试该功能。参考仓库的公开验证摘要未明确展示 ro.adb.secure=1 的读数；不能将其外推到全部安全认证 ROM。若 ROM 缺少完整授权处理，或仍要求已被删除的确认界面，重启不能修复。

## 关闭 ADB 并恢复 USB 模式

当前 Z7X 的 `/vendor/etc/init/hw/init.m7642.usb.rc` 明确以注释 `set mtp as default to being host mode` 标识其默认主机模式。应用先读取并确认该脚本特征，否则拒绝执行；这并非所有 ROM 的通用默认值。

用户确认后：

1. 保存手动开启模式，并关闭开机恢复。
2. 将持久和当前 ADB 端口设为 -1。
3. 将持久和当前 USB 配置设为 none，并请求停止 adbd。
4. 将持久和当前 USB 配置设为 mtp，读回核对。
5. 检查 adbd 是否 stopped，报告结果。

电脑 ADB 可能在中途断开，后续步骤由投影仪本地应用继续执行。失败时可能已有部分设置生效，界面会报告未完成；不宣称事务回滚。此操作不清除用户数据、不清除电脑授权、不恢复整机出厂设置。

完成后重新插入 U 盘检查，必要时重启投影仪。再次打开应用不会自动开启 ADB；需要使用时手动点“重新开启并检查”。开机恢复仍需单独开启。U 盘功能正常时不要使用。
